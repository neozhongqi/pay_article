# AI支付时代，用户的「支付授权」如何保障？

> 主题编号：S-01  
> 匹配热点：中国支付清算协会《智能体支付应用自律公约》落地讨论、AI钱包/Token Pay/代理支付授权争议  
> 成稿日期：2026-10-19  
> 目标读者：安全专家、支付产品经理、持牌支付机构合规与风控人员

---

## 一、热点从「会不会花钱」变成「谁有权替你花钱」

2026年10月上旬，智能体支付再次成为行业议论中心。经济日报以「拧紧智能体支付应用安全阀」为题，把一个原本偏产品演示的话题拉回监管与用户信任：当人工智能从「出主意的参谋」变成「能花钱的助手」，用户真正担心的不是模型够不够聪明，而是钱能不能管住。

几乎同一时间，行业媒体对 Stripe、蚂蚁、腾讯、京东、银联等机构的密集落子做了复盘。结论高度一致：演示可以做到「说一句话就下单」，落地却卡在三个尚未被产品完全回答的问题上——

1. 谁来决定买哪个套餐？  
2. 谁来确认这一笔支付？  
3. 决策失误后，责任落在用户、商户、模型厂商，还是持牌支付机构？

这正是记忆主题库 S-01 的核心：AI 支付时代，用户的「支付授权」如何保障。它同时咬合 H-01（AI钱包）、H-02（Token Pay）、H-04（AI Agent 从工具变成管家）和 H-07（从「碰一下」到「说一句」）。换句话说，今天的热点不是又一个新入口，而是支付权利结构被改写。

传统支付里，授权几乎等于「本人当场确认」：密码、指纹、刷脸、扫码，都是人在场、人拍板。智能体支付把这个动作拆开了。用户可能只说了一句「帮我订下午两点的电影票，顺路买杯冰美式」，后面的选座、比价、下单和扣款，都可能由软件系统连续完成。授权不再是一次点击，而变成一组事先划定、事中校验、事后可追溯的边界。

如果这组边界画不清楚，行业会同时掉进两类坑：一类是不敢放权，智能体永远停在「帮你打开收银台」；另一类是放权过猛，模型幻觉、提示词注入、越权调用，会把用户资金和反洗钱防线一起冲垮。

## 二、痛点并不抽象：授权一旦含糊，整条交易链都会失真

把近期公开讨论里的抱怨摊开，智能体支付的授权痛点可以收成五条。

**第一，意愿核验被自然语言稀释。**  
用户说「帮我看看附近有什么团购」，和「帮我把这家店的套餐买了」，语义距离很近，资金后果完全不同。大模型擅长补全意图，也最容易过度推断。一旦系统把「看看」理解成「下单」，后面所有风控都是在给一次错误授权擦屁股。

**第二，账户边界被主账户习惯绑架。**  
多数人仍把微信零钱、支付宝余额理解成「我的全部支付能力」。如果智能体直接挂在主账户上，限额、场景和可撤销性都很难做细。用户要么不敢开，要么开了以后每一次都高度紧张。

**第三，责任锚点消失。**  
人点确认时，责任链条相对清楚：平台负责通道和风控，商户负责履约，用户承担最终授权。智能体一旦在授权范围内自行决策，就会出现新问题：买错了算谁的？模型输出随机、逻辑不透明，正好击中支付最不能容忍的一点——资金交易必须可解释、可审计、可追责。

**第四，机器交易把旧风控当成敌人。**  
今天的互联网支付基础设施是为人类页面、表单、验证码和确认按钮设计的。大量 Bot 发起支付，旧系统会优先当成攻击。而智能体商业的方向，恰恰是让软件代表用户高频、小额、跨平台地完成交易。不重建授权与身份，风控只会在「拦掉全部」和「放任全部」之间摇摆。

**第五，跨境和平台互操作把授权问题放大。**  
2026年9月的跨境企业支付调研里，平台收款、多币种管理、汇率波动、合规成本和资金效率已经是企业侧三大痛点。智能体一旦进入采购、对账和付款，授权不再只是 C 端「笔笔确认」，还要回答：这个 Agent 代表哪家公司、哪本账、哪个币种、哪条合规规则。企业支付的 KYA（了解你的智能体）会比个人侧更难。

这些痛点加在一起，解释了为什么 2026 年行业一边发布 AI 钱包、Token Pay、Agent Pay，一边把「授权协议、交易限额、笔笔确认、资金隔离」反复写成产品卖点。卖点背后，其实是怕。

## 三、规则已经给出底线：授权必须写成可执行的合同，而不是一句「用户同意」

中国支付清算协会于 2026 年 8 月 24 日印发《智能体支付应用自律公约》（中支协发〔2026〕128号），并在 10 月的舆论场中被再次解读。对支付机构来说，这份文件最有用的不是口号，而是把授权从原则拆成了可落地的条款。

公约把智能体支付应用定义为：会员单位利用大模型等人工智能技术，在用户授权的前提下，根据用户真实意思表示，使用智能体与电子商务等数字服务交互，发起和执行支付指令。适用范围覆盖账户管理、交易处理、收单、转接清算等会员单位。这意味着，智能体可以出现在对话里，但支付核心环节仍必须落在持牌机构身上。

授权管理至少有四条硬约束：

1. **授权边界必须写进协议。** 交易限额、扣款账户和优先级、有效期，以及智能体代为操作、访问数据、调用 API 的权利义务，都不能只靠产品文案暗示。  
2. **身份和交易意愿必须核验。** 「用户说过一句话」不等于「用户确认了这一笔」。  
3. **严防越权支付。** 系统只能按照授权执行，并保证交易完整、真实、可追溯。  
4. **用户随时可以撤销授权。** 没有退出键的授权，本质上是把账户长期租给模型。

安全管理和责任原则同样直接对准授权失效后的后果：通过交易限额防范超额支取和越权划转；对用户授权、模型决策、支付指令、风险控制做可信存证；坚持「谁应用人工智能技术谁负责」「谁提供支付服务谁负责」；把模型幻觉、注入攻击、指令篡改纳入全面风险管理。跨智能体平台调用、大额交易被明确列为应审慎开展的高风险场景。

协会还给出了阶段论：智能体辅助支付、预设条件下的智能体自主支付、泛条件智能体自主支付。后两阶段在正式对外提供服务前，须向协会报备，并通过业务有效性、技术安全性、伦理符合性评估，配套人工服务、监控、应急和回退机制。央行方面此前也提醒过：大模型和自主智能体具有输出随机、逻辑不够透明的特征，如果盲目赋予交易决策权限，会动摇资金交易的信任基础。

把这些要求翻译成产品语言，就是一句话：**授权不是勾选框，而是一套可编程、可撤销、可举证的资金权限。**

## 四、产品和协议正在围栏化：先给智能体一张「受限制的卡」

规则画了红线，市场已经在用产品把红线做成体验。

微信支付的路径最容易被用户理解。AI 专属卡把智能体可用资金从主账户里拆出去：主账隔离、余额用户自定、每一笔仍需本人在手机端确认。它很像给智能体开的「亲子卡」——孩子可以去办事，但预算、场景和最终拍板权仍在家长手里。对用户而言，这降低了「AI 把我零钱花光」的想象空间；对机构而言，这把责任锚点暂时留在「人确认」这一跳。

支付宝走的是另一条更靠近消费闭环的路。AI 付强调智能体可以在授权下完成下单和支付，但资金变动仍需本人确认；面向个人的 AI 钱包则把支付前任务管理、支付中控制和支付后账单查询做成全程可视；Token Pay 先解决大模型与云厂商的订阅和席位采购；Agent Pay 则连接智能体平台与商家，让 Agent 在授权范围内完成下单、支付和凭证回传。支付宝还把能力拆成 Vibe Pay、Skill Pay、Machine Pay、Token Pay、Agent Pay 一组矩阵，说明它已经意识到：AI 支付不是一个收银台，而是多种交易对象、多种计费方式和多种授权粒度的组合。

银联更靠基础设施。智能体支付开放协议框架的目标，是跨机构、跨平台、跨场景的互联互通，而不是再做一个 C 端超级入口。蚂蚁国际与 Visa、Mastercard 推进的 KYA 协同，以及京东的智能体自主支付协议，都在回答同一个问题：智能体作为新的交易主体，如何被识别、被授权、被各网络共同信任。

海外同步在建机器可读的支付请求。Stripe 与稳定币公链合作的机器支付协议，强调智能体不必再去操作人类结账页，而是直接接收结构化支付请求并在授权范围内付款。这类协议更适配 API 调用、Token 消耗、数字内容授权等「高频、小额、人对细节无感」的场景；短板也很清楚：线下覆盖弱，大额交易的信任背书仍不如卡组织。

这些方案看似路线不同，授权哲学其实高度收敛：

- 先隔离资金，再谈自主；  
- 先限额和场景，再谈免确认；  
- 先人机共决，再谈预设条件下的自动执行；  
- 先可撤销、可追溯，再谈体验流畅。

这也解释了为什么有观察认为，微信和支付宝目前仍处在「AI 辅助支付」到「预设条件自主支付」的过渡带，还没有把开放式支付决策权交给模型。2026 年可以被称作 AI 进入支付领域的元年，但元年的正确姿势不是让智能体随便花钱，而是先长出围栏。

## 五、一套可落地的授权框架：从「确认按钮」升级为「权限操作系统」

结合公约条款和头部产品实践，支付机构要把 S-01 做成可上线能力，至少需要六层设计。

### 1. 主体层：KYC 之后必须有 KYA

只认识用户不够，还要认识这个用户授权了哪一个智能体。KYA 至少应覆盖：智能体开发者身份、模型/应用版本、调用权限范围、历史风险评分、是否允许被第三方 Agent 二次调用。没有 KYA，授权协议签了也等于签给了一团会变形的代码。

外部智能体接入时，持牌机构不能把风控外包给模型厂商。公约要求加强对外部开发者和服务提供者的合作风险管控，本质是：通道可以开放，主体责任不能开放。

### 2. 合约层：把限额、账户、期限写成机器可执行规则

授权协议不应只是用户协议里的法律段落，而应落成支付核心可拦截的规则：

- 单笔限额、累计限额、日/周/月限额；  
- 指定扣款账户和优先级，禁止「余额不够就顺手划主账户」；  
- 授权有效期，到期默认关闭而不是默认续期；  
- 允许的商户类目、地区、币种、时段；  
- 是否允许订阅、自动续费、分账、退款原路；  
- 用户一键撤销后，在途指令如何冻结或回滚。

对 C 端，这表现为「AI 专属卡 + 场景白名单」；对 B 端，这表现为「企业账户 + 部门预算 + 审批流 + Agent 身份」。跨境场景还要加上：能否换汇、能否出境、对应哪条贸易或服务申报口径。

### 3. 意愿层：把自然语言翻译成可核验的支付意图

这是当前最容易被产品忽略、也最容易出事的一层。建议把用户表达拆成三级：

- **浏览级**：查询、比较、推荐，默认不得发起支付；  
- **备货级**：生成订单草稿、锁库存、算价，必须二次确认；  
- **成交级**：明确含有购买、支付、扣款语义，且金额、收款方、商品要素完整，才允许拉起支付。

大额、跨境、预付、投资理财、转账给陌生对手盘，应强制回到人确认，哪怕用户曾经给过较宽授权。公约把大额交易和跨智能体平台调用列为审慎场景，不是保守，而是承认模型在这些场景里的错误成本不可逆。

意愿核验还要防提示词注入和会话劫持。用户对智能体说的话，不能被网页、邮件、第三方 Skill 里的隐藏指令改写成支付命令。支付机构需要的不是「模型更听话」，而是「支付指令在出模型之后，仍能被独立校验」。

### 4. 资金层：专款专用，主账户默认不可达

微信 AI 专属卡已经证明，资金隔离是用户最容易理解的安全感来源。支付机构应把「智能体可用余额」做成一等公民账户属性，而不是商户侧的虚拟额度。原则很简单：

- 智能体碰不到主账户；  
- 用户决定放多少钱进去；  
- 超出余额不是降级去主账户扣，而是失败并提示；  
- 退款、撤销、差错争议都回到这张专属容器，避免和日常消费流水搅在一起。

对预付、会员、企业备用金，专属容器还要满足备付金和预收资金监管，不能借「AI 钱包」之名形成新的沉淀资金灰区。

### 5. 证据层：授权、决策、指令、风控必须能回放

公约要求对用户授权、模型决策、支付指令、风险控制形成可验证、可追溯、不可篡改的证据链。这决定了争议出现时，机构拿得出「当时用户到底授权了什么」。

最低可行存证应包括：授权协议版本、生效和撤销时间、当笔意图原文、模型/Agent 标识、订单要素、核验方式、限额校验结果、用户确认动作、最终支付指令。没有这条证据链，所谓「可解释、可审计」就是空话，客诉和监管检查都会把机构逼回全人工。

### 6. 治理层：分级分类，先报备再放开自主

不是所有智能体支付都该一个开关。可按风险分成三档：

- **L1 辅助支付**：智能体只负责发现和填单，人确认支付。可广泛开展。  
- **L2 预设条件自主支付**：小额、高频、白名单商户、明确预算内，允许免逐笔确认，但必须可瞬间关闭。上线前报备。  
- **L3 泛条件自主支付**：模型在较宽目标下自行选品和付款。当前应视为实验区，而不是默认能力。

分期推进的好处是：用户信任可以积累，机构也能用真实客诉和欺诈数据校准限额，而不是用演示视频代替风控模型。

## 六、给持牌机构的十条落地清单

1. 把智能体支付从「增长项目」改挂到「持牌业务 + 消费者保护」双负责人机制，避免产品节奏压过合规。  
2. 重新梳理授权协议模板，限额、账户、期限、撤销、数据调用必须可被核心系统执行。  
3. 上线 KYA：每个能发起支付的 Agent 都要有身份、版本、权限和风险评分。  
4. 默认开通资金隔离容器，禁止智能体直连用户主账户。  
5. 建立自然语言意图分级，浏览语不得触发扣款。  
6. 大额、跨境、预付、转账、跨 Agent 调用维持人工确认。  
7. 为授权、决策、指令、风控单独做存证，而不是事后从日志里拼。  
8. 将模型幻觉、提示词注入、指令篡改纳入现有交易监控，而不是另起一套「AI 安全」孤岛。  
9. 自主支付类应用先评估、先报备、先小流量，再谈规模化。  
10. 给用户一个比开通更显眼的关闭入口，并把账单做成「这个智能体今天替我花了什么」。

这十条看起来像在给创新加刹车。实际上，2026 年的竞争已经不再比谁先喊出「说句话就能付」，而是比谁先把授权做成用户敢用、监管认账、出了事能讲清楚的基础设施。

## 七、结论：授权做对了，智能体才能从工具变成管家

回顾 10 月这轮热点，行业争论的表面是 AI 钱包、Token Pay、Agent Pay、机器支付协议谁更先进，底层却都指向 S-01：用户到底怎样把花钱的权利交给一个会自己行动的软件。

公约已经把底线写死：用户授权、最小必要、全程防护；持牌机构对账户、资金和信息安全承担主体责任；自主支付必须分阶段、限额、可撤销、可追溯。微信、支付宝、银联和海外卡组织、收单机构的产品，则把这条底线翻译成了专属卡、笔笔确认、任务可视、KYA 和机器可读支付请求。

下一步真正难的，不是再发一个 Skill 或再接一个大模型，而是让授权从「最后那个确认按钮」长成一套权限操作系统。谁能在体验不太坏的前提下，把意愿核验、资金隔离、限额治理和证据链做成默认能力，谁才有资格谈「替你付」。在那之前，所有「管家」都还只是自备零花钱、事事要汇报的助理。

对用户来说，判断一个 AI 支付产品是否值得开通，标准其实很朴素：它能不能清楚告诉我，这个智能体能花我哪笔钱、花多少、花去哪、我怎么立刻停掉，以及出事之后谁来认。答不全这五句，就还不是管家，只是一个更会说话的收银台。
